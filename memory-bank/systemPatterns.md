## Purpose

Use this file to document the system architecture, key design patterns, and
important technical decisions that shape how the project is built.

## When to Update It

Update this file when:

- the architecture changes
- a new design pattern becomes standard in the codebase
- an important technical decision is made or reversed
- the relationship between major components changes

## What to Include

- the high-level architecture
- important component relationships
- recurring design patterns and conventions
- major architectural decisions and the reasoning behind them

## What to Avoid

- feature status updates
- detailed implementation dumps or full code blocks
- short-lived task notes that belong in `activeContext.md`
- secrets or environment-specific credentials
