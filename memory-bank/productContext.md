## Purpose

Use this file to explain the product perspective of the project.
It should capture who the users are, what problems are being solved, and what
kind of experience the project is meant to provide.

## When to Update It

Update this file when:

- user needs change
- the product direction changes
- the intended user experience changes
- major business or usability assumptions change

## What to Include

- why the project exists
- the user or audience it serves
- the main problems it solves
- user experience goals and expectations
- high-level product context that helps guide design choices

## What to Avoid

- implementation-specific architecture details
- temporary status updates
- large code snippets
- secrets or private business data that should not live in documentation
